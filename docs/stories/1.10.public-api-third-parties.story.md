# Story 1.10 — API pública para terceiros

## Status
Ready for Review

## Priority
P1 — Cobertura de formulários

## Story
**Como** desenvolvedor integrando um formulário próprio ou de terceiro sem integração nomeada,
**quero** helpers e hooks documentados para renderizar o campo e verificar a submissão,
**para que** eu não precise reimplementar a lógica de verificação.

## Backlog / Arquitetura
- B-11, FR-11 (arquitetura v1 §12)

## Acceptance Criteria

1. Três funções globais implementadas exatamente com a assinatura da arquitetura v1 §12:
   - `wp_recaptcha_forms_render_field( string $form_id, array $args = [] ): void` — imprime só o hidden field (nada específico de usuário, A3).
   - `wp_recaptcha_forms_verify( string $form_id, array $args = [] ): bool|WP_Error`.
   - `wp_recaptcha_forms_is_active( string $form_id = '' ): bool`.
2. Filtros documentados e funcionais: `wp_recaptcha_forms_should_protect`, `wp_recaptcha_forms_verdict`, `wp_recaptcha_forms_error_message`, `wp_recaptcha_forms_endpoint` (já coberto pela Story 1.2), `wp_recaptcha_forms_misconfig_policy` (Story 1.3), `wp_recaptcha_forms_request_timeout` (Story 1.2).
3. Exemplo de `wp_recaptcha_forms_should_protect` na documentação **não** usa "bypass por capability de usuário logado" como exemplo (resolve OB-04 — esse exemplo colide com o escopo explicitamente excluído B-23; usar outro cenário, ex.: desligar em ambiente de staging).
4. Contrato tratado como estável desde a v1 — qualquer mudança de assinatura é MAJOR (documentado no CHANGELOG/versioning, não é código desta story).
5. Registrar formulário de terceiro no Registry para ganhar toggle na UI **explicitamente fora da v1** — não implementar `wp_recaptcha_forms_register_integration`.
6. Testes unitários dos três helpers e dos filtros, incluindo o caso `is_wp_error()` sem try/catch.
