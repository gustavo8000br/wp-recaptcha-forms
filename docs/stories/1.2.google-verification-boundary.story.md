# Story 1.2 — Fronteira de verificação do Google (Provider/Transport)

## Status
Draft

## Priority
P0 — Fundação

## Story
**Como** mantenedor do plugin,
**quero** que todo conhecimento sobre o endpoint, vocabulário de erro e formato de resposta do Google fique isolado num único diretório testável sem rede,
**para que** trocar de endpoint (recaptcha.net, futura migração Enterprise) seja reescrever uma classe, não caçar strings pelo código.

## Backlog / Arquitetura
- B-02, FR-02 (arquitetura v1 §4)
- R-04 (isolamento da fronteira HTTP)

## Acceptance Criteria

1. `ProviderInterface` implementado com `verify()`, `version()`, `script_url()`; `verify()` nunca lança exceção — falha sempre vira `ProviderResponse`.
2. `VerificationRequest` e `ProviderResponse` são imutáveis. `ProviderResponse::debug_codes()` existe e só é consumido em log/admin, nunca em lógica de decisão.
3. `TransportInterface` com `WpHttpTransport` (embrulha `wp_remote_post`, timeout 5s filtrável via `wp_recaptcha_forms_request_timeout`, `redirection => 0`, `sslverify => true`) e `FakeTransport` para testes (injeção direta, sem depender do hook global `pre_http_request`).
4. `src/Provider/Endpoints.php` é o único arquivo do repositório com a string `recaptcha/api`. Filtro `wp_recaptcha_forms_endpoint( $url, $which )` documentado e testado (cobre o caso `recaptcha.net`).
5. Gate de CI `bin/check-boundary.sh` implementado com as duas verificações de grep da arquitetura §4.5, **sem a armadilha de `pipefail`** (resolve OB-06 — script deve funcionar corretamente sob `set -o pipefail` ou documentar explicitamente por que não usa).
6. Nenhuma classe/arquivo fora de `src/Provider/` referencia `error-codes` do Google (`invalid-input-`, `timeout-or-duplicate`) — verificado pelo gate de CI.
7. Testes unitários com `FakeTransport` cobrindo: sucesso, timeout, HTTP 5xx, HTTP 429, corpo não-JSON, corpo vazio — sem rede real.

## Tasks / Subtasks
