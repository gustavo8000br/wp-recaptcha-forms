# Story 1.7 — Formulários nativos WP: comentário, registro, lost-password

## Status
Ready for Review

## Priority
P1 — Cobertura de formulários

## Story
**Como** operador,
**quero** proteger comentários, registro de usuário e recuperação de senha nativos do WordPress, cada um com toggle próprio,
**para que** eu cubra os formulários mais atacados sem depender de plugin pago.

## Backlog / Arquitetura
- B-08 (parcial — login é a Story 1.8), B-09 (fallback de bloqueio, base)

## Acceptance Criteria

1. `Core\CommentIntegration`, `Core\RegisterIntegration`, `Core\LostPasswordIntegration` implementam `IntegrationInterface` (`id()`, `label()`, `available()`, `register()`) e são registradas no `Registry::boot()` incondicionalmente.
2. Cada integração tem toggle independente na tela de configurações (via Registry — Story 1.5).
3. Comentário: campo renderizado via `comment_form`, validado em `preprocess_comment`; recusa com `wp_die()` contendo mensagem clara e link de volta (conteúdo do comentário é perdido — comportamento documentado, não é regressão).
4. Registro: validado via `registration_errors`, preservando os campos já digitados (username/email) no reload.
5. Lost password: validado via `lostpassword_post`, com `WP_Error` preservando o e-mail/login digitado.
6. Todos os três usam o mesmo `Gate::assess()` (Story 1.3) — nenhuma lógica de decisão duplicada nos adaptadores.
7. Mensagem de recusa distinta por classe de falha (REJECTED / INFRA bloqueado / CLIENT_UNREACHABLE bloqueado), reutilizando os textos de `Messages` (Story 1.20 define a estrutura i18n).
8. Testes de integração: submissão com token válido passa; com token ausente e `cstate=''` bloqueia; com toggle desligado passa sem chamar o Gate.
