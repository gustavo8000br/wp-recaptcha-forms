# Story 1.8 — Formulário nativo WP: login (com exclusões XML-RPC/REST/CLI/cron)

## Status
Ready for Review

## Priority
P1 — Cobertura de formulários (risco alto, mecanismo já roteirizado pela arquitetura)

## Story
**Como** operador,
**quero** proteger o formulário HTML de login do `wp-login.php` sem afetar XML-RPC, REST API, WP-CLI, cron ou apps oficiais,
**para que** eu não perca acesso a integrações legítimas nem tranque usuários fora por engano.

## Backlog / Arquitetura
- B-08 (login), FR-08, D-07 (resolvido: login está no escopo)
- BL-04 — fronteira do login (arquitetura v1.1 §6, nova §8.6 do v1)

## Acceptance Criteria

1. Campo renderizado via `login_form` (**nunca** `login_footer`) — precisa estar dentro do `<form>` para ser submetido.
2. Validação via `add_filter('authenticate', [...], 30, 3)` — prioridade 30, depois das checagens de credencial do core.
3. `applies()` implementado exatamente como a arquitetura v1.1 §6.3 especifica: retorna `false` para `XMLRPC_REQUEST`, `REST_REQUEST`, `WP_CLI`, `wp_doing_cron()`, `wp_doing_ajax()`, método != POST, ausência de `$_POST['wp-submit']`, e usuário já logado (`is_user_logged_in()`).
4. Recusa via `WP_Error` com código específico por classe: `wrf_login_blocked` (REJECTED), `wrf_login_client_unreachable` (CLIENT_UNREACHABLE bloqueado), `wrf_login_unavailable` (INFRA bloqueado). MISCONFIG nunca bloqueia o login (fail-open + notice).
5. `WP_Error` no `authenticate` preserva o username digitado no reload do `wp-login.php` (comportamento nativo do hook, sem código extra).
6. Toggle independente do form `wp_login`, distinto de registro (`wp_register`) e lost-password (`wp_lostpassword`).
7. **Reset password (link por e-mail) permanece fora de escopo** — não é tocado por esta story.
8. Testes (mínimo, conforme v1.1 §6.6):
   - `applies()` retorna `false` para cada uma das sete condições de exclusão — 7 asserções unitárias, sem rede;
   - integração: `wp_authenticate()` com credenciais válidas e nenhum campo do plugin, sob `XMLRPC_REQUEST` → `WP_User`, não `WP_Error`;
   - integração: POST em `wp-login.php` com `wp-submit` e token vazio/`cstate=''` → `WP_Error` `wrf_login_blocked`;
   - integração: mesmo POST com `cstate=no-script` e política `allow` → autentica.
