# Story 1.5 — Tela de configurações

## Status
Draft

## Priority
P0 — Fundação

## Story
**Como** dono de loja sem conhecimento técnico (persona P1),
**quero** uma tela de configurações autoexplicativa com validação de chaves, thresholds e política de falha por dois eixos,
**para que** eu configure o plugin sem precisar entender a arquitetura por trás.

## Backlog / Arquitetura
- B-05, FR-05; B-06, FR-06 (arquitetura v1 §5.3-1, §7.2)
- Arquitetura v1.1 §7.4 (UI de dois eixos), §4.3 (sonda no save)

## Acceptance Criteria

1. Menu admin registrado, tela via Settings API, nonce, capability `manage_options` em toda ação (incluindo AJAX de validação de chave).
2. Campos: seleção de versão (v3/v2), site key, secret key (mascarada — salvar vazio mantém o valor atual, nunca ecoada em claro), threshold (default 0.6, só relevante para v3), mensagens de erro customizáveis, toggles por formulário — **a tela é gerada a partir do `Integrations\Registry`** (Story 1.11), não escrita à mão form a form.
3. Suporte a `WP_RECAPTCHA_FORMS_SECRET_KEY` via `wp-config.php`: quando definida, tem precedência sobre a option e o campo aparece desabilitado na UI com nota explicando a origem.
4. Sanitização de todos os campos (`Sanitizer.php`); todos os campos livres (mensagens customizadas) passam por `wp_kses`.
5. Sonda de validação no save: `siteverify` com token deliberadamente inválido; espera `invalid-input-response` como prova de secret válida. Se vier `invalid-input-secret`, o save é recusado com erro no campo. UI/README **não afirmam "chaves validadas"** — só "secret validada" (correção de escopo honesta da v1.1 §4.3).
6. Dois eixos de política de falha na tela: seção global com dois selects rotulados em linguagem de operador ("Se o nosso servidor não conseguir falar com o Google" / "Se o navegador do visitante não conseguir carregar o reCAPTCHA") e, por formulário, uma coluna "Quando falhar" com `Herdar / Permitir ambos / Bloquear ambos / Personalizado…`.
7. Estado do plugin visível no topo da tela: `Protegendo` / `Degradado — não verificando` / `Desativado` — refletindo MISCONFIG (Story 1.3) e `WRF_DISABLE` (Story 1.1).
8. Avisos e ajuda contextual: ao escolher v2, aviso recomendando gerar chave v3 nova; links para os **dois** fluxos de obtenção de chave (console clássico e Google Cloud/Enterprise — ver Story 1.22 para o texto completo em README; aqui só os links da tela de config), com um marcado como recomendado. URLs verificadas ao vivo antes do release (gate de release, não desta story).
9. Sem WooCommerce ativo, a seção Woo não aparece na tela (comportamento automático via Registry — Story 1.11), não é código condicional escrito à mão aqui.
