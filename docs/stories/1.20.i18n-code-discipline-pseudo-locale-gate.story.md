# Story 1.20 — Disciplina de i18n no código + gate de pseudo-locale (CI)

## Status
Draft

## Priority
P0/P2 híbrida — **entra cedo, junto da fundação**, mas o gate vira bloqueante de CI apenas com o critério fechado (ver AC 8, BL-05)

## Story
**Como** mantenedor,
**quero** que toda string exibível passe por i18n corretamente desde a primeira linha de código, e que um teste de CI prove isso de ponta a ponta,
**para que** nenhuma string hardcoded chegue ao release e a deriva de tradução (R-08) seja pega antes da revisão de PR.

## Backlog / Arquitetura
- FR-25, FR-28 (arquitetura v1 §9.1, §9.5)
- BL-05 — critério do pseudo-locale precisa ser fechado antes de o teste ser gate bloqueante (qa-plan-review-v1 §1)

## Acceptance Criteria

1. Text domain `wp-recaptcha-forms`, `Domain Path: /languages` (já no header, Story 1.1); `load_plugin_textdomain()` no hook `init` (já implementado na Story 1.1) — esta story adiciona a **regra de revisão de código** e a verificação automatizada.
2. Regra aplicada em todo o código: nenhuma chamada a `__()`/`_e()`/etc. no escopo de arquivo, `const` ou propriedade de classe — só dentro de método, executado após `init`. Mensagens default vivem em métodos (`Messages::*()`), nunca em `const`.
3. **Critério do pseudo-locale `en_CA` fechado (resolve BL-05), antes deste gate ser bloqueante:**
   - o teste avalia **as strings retornadas pelos métodos do plugin**, não o HTML renderizado inteiro (mais barato e estável que delimitar por container DOM);
   - allowlist fechada e versionada de termos que nunca são traduzidos (nomes próprios: "WooCommerce", "reCAPTCHA", "Google", "Newsletter", chrome nativo do admin do WP) — alterar a allowlist exige justificativa explícita no PR;
   - valores de opção digitados pelo operador (mensagens customizadas do FR-27) são explicitamente excluídos da varredura;
   - placeholders de `sprintf` (`%s`, `%d`) e formas plurais são preservados pelo pseudo-locale, não quebram o render.
4. `bin/i18n-pseudo.php` gera o pseudo-locale `en_CA` a partir do `.pot`, traduzindo cada `msgid` para `⟦<msgid>⟧`.
5. `bin/i18n-e2e.sh`: gera `.pot` do zero, deriva `en_CA`, compila `.mo`/`.l10n.php`, roda teste de integração que ativa `switch_to_locale('en_CA')`, renderiza a tela de config e as mensagens de erro do front, e afirma: toda string do escopo definido no AC 3 está entre `⟦ ⟧`; nenhuma está fora. Apaga os artefatos ao final.
6. `--check` do `i18n-progress` (Story 1.21) ignora comentários de referência `#: arquivo:linha` do `.pot` na comparação — resolve a parte do BL-05 que afeta PRs que só movem código.
7. Gate entra no CI (Story 1.18) como bloqueante **somente depois** que os itens 3 e 6 estiverem implementados e testados — não antes.
