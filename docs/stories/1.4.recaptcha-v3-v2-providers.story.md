# Story 1.4 — Providers reCAPTCHA v3 e v2 checkbox

## Status
Draft

## Priority
P0 — Fundação

## Story
**Como** operador,
**quero** escolher entre reCAPTCHA v3 (invisível, por score) e v2 checkbox,
**para que** eu tenha uma alternativa selecionável caso o v3 não sirva para o meu caso de uso.

## Backlog / Arquitetura
- B-03, FR-03; B-04, FR-04 (arquitetura v1 §4.2)

## Acceptance Criteria

1. `SiteverifyV3` e `SiteverifyV2` implementam `ProviderInterface`, compartilhando `AbstractSiteverifyProvider` (transporte e parsing comuns).
2. v3: token gerado por `action` nomeada por formulário (mesma `action` usada em `expected_action` na verificação); score comparado contra o threshold global configurado (default 0.6). Score abaixo do threshold → REJECTED (classificado pela Story 1.3, aqui só a chamada correta com `expected_action`).
3. v2: `ProviderResponse::score()` retorna `null`; validação é só `success`/`hostname`.
4. `ProviderFactory` seleciona a implementação conforme a opção de versão salva (v3/v2).
5. `script_url()` de cada provider aponta para `api.js` (v3) e a URL equivalente do widget v2, respeitando o filtro `wp_recaptcha_forms_endpoint`.
6. Token válido com score/action corretos → ALLOW. Token com score abaixo do threshold ou action divergente → BLOCK com mensagem clara (delegando ao `Gate` da Story 1.3).
7. Testes unitários cobrindo threshold (score exatamente no limite, acima, abaixo) e action divergente, via `FakeTransport`.
