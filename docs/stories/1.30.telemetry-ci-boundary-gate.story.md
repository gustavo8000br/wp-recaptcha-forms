# Story 1.30 — Gate de CI: nada que revele o site dentro de `src/Telemetry/`

## Status
Ready for Review

## Priority
P1 — barato e fecha o vazamento mais fácil de cometer no desenho inteiro (o domínio no User-Agent / num campo do payload).

## Story
**Como** mantenedor,
**quero** um gate automático que reprove qualquer uso de `site_url`/`home_url`/`get_bloginfo` (e afins) dentro de `src/Telemetry/`,
**para que** o princípio "o envelope descreve a origem sem identificar o site" continue verdadeiro daqui a dois anos, sem depender de revisão humana.

## Backlog / Arquitetura
- `docs/telemetry-design.md` §6.2 ("candidato natural a gate de CI ... um `grep` que proíba `site_url`/`home_url`/`get_bloginfo` dentro de `src/Telemetry/`"), no espírito do gate de fronteira da v1.1 §8.2
- Estende `bin/check-boundary.sh` (mesmo padrão robusto sob `pipefail`, testa conteúdo e não exit code)
- Depende de 1.29 (o diretório `src/Telemetry/` existe)

## Acceptance Criteria

1. `bin/check-boundary.sh` ganha um bloco novo que roda `grep -rnE` sobre `src/Telemetry/` procurando:
   - `site_url`, `home_url`, `get_bloginfo`, `network_site_url`, `network_home_url`;
   - `get_option\(\s*['"](siteurl|home|blogname|admin_email)['"]`;
   - `\$_SERVER\[['"]HTTP_HOST` e `\$_SERVER\[['"]SERVER_NAME`.
2. Qualquer ocorrência → `fail` com o path:linha, e o script sai com código ≠ 0 (`FAILED=1`, como os demais blocos).
3. Zero ocorrência → `pass 'src/Telemetry/ não revela identidade do site'`.
4. O bloco segue o padrão do arquivo: captura em variável com `|| true`, testa `-n "$HITS"`, roda correto com e sem `set -o pipefail`.
5. Exceção controlada, se necessária: `User-Agent` é `'wp-recaptcha-forms/' . WRF_VERSION` — constante, não função — então não casa nenhum padrão. Se algum ponto legítimo precisar de `get_locale()`/`determine_locale()`, isso **não** está na lista de proibidos (locale não é URL) — deixar explícito em comentário no script.
6. `composer check:boundary` continua passando (os 6 gates atuais + o novo) numa árvore com `src/Telemetry/` já implementado.
7. O gate roda no CI: `ci.yml` já executa `composer check:boundary` em push/PR para `main` — confirmar que o novo bloco entra nesse mesmo passo (nenhuma mudança de workflow necessária além de garantir que o script é o mesmo).
8. Teste: um arquivo de fixture temporário em `src/Telemetry/` contendo `home_url()` faz `check:boundary` reprovar (pode ser um teste de shell no CI ou um caso documentado em `tests/` que cria/apaga o fixture; se for custoso, um passo `--dry-run` no próprio script que aceita um diretório alternativo).

comentário seria mais frágil que a regra que ele protege. `src/Telemetry/Consent.php` já
foi escrito nessa disciplina (Story 1.27) — descreve a armadilha do hash de domínio sem
nomear a função.

**O script passou a aceitar um diretório como `$1`** (default `src/Telemetry/`). É o que
torna a AC 8 barata: o teste roda o gate real sobre um fixture em `sys_get_temp_dir()`,
sem plantar arquivo dentro de `src/` — o que deixaria lixo no repositório se a suíte fosse
interrompida no meio. O parâmetro não muda o comportamento de `composer check:boundary`.

**AC 7:** `.github/workflows/ci.yml` linha 66 e `release.yml` linha 39 já executam

**Verificado:** `tests/Unit/Telemetry/TelemetryBoundaryGateTest.php` — 14 casos. Os 11
padrões proibidos (incluindo a menção em comentário) fazem o script sair com código ≠ 0;
`get_locale()`/`determine_locale()` e o User-Agent real (`'wp-recaptcha-forms/' .
WP_RECAPTCHA_FORMS_VERSION`, constante) **não** reprovam; e o `src/Telemetry/` de verdade
passa — o gate nasceu como trava, não como dívida, que é o resultado que a story
descreve como desejado. `composer check:boundary`: **7/7**.

## Dev Notes
- Não usar `grep` nativo do Claude Code aqui — o gate é um script shell versionado que roda no CI e localmente; é código de produção do repositório, não uma busca de desenvolvimento.
- A mensagem de `fail` deve explicar **por quê**: "o envelope descreve a origem sem identificar o site (telemetry-design §1.4, §6.2)". Um gate que reprova sem dizer o motivo vira `phpcs:ignore` na primeira pressa.
- Se a Story 1.29 já tiver sido escrita com a disciplina (deve ter), este gate passa de primeira e serve só de trava. É o resultado desejado.
