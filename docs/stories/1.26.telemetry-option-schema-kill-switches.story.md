# Story 1.26 — Schema da opção `telemetry` e chaves de desligamento

## Status
Ready for Review

## Priority
P1 — fundação da feature de telemetria. Tudo em 1.27–1.34 depende desta.

## Story
**Como** operador (e como operador de hospedagem gerenciada),
**quero** que exista uma opção `telemetry` desligada de fábrica e uma constante dedicada para desligá-la por `wp-config.php`,
**para que** nenhuma instalação envie dado sem opt-in explícito e para que quem administra por arquivo consiga desligar a telemetria de toda a frota sem tocar no banco.

## Backlog / Arquitetura
- `docs/telemetry-design.md` §4.1 (a opção, as regras não negociáveis, `WRF_TELEMETRY_DISABLE`)
- §7 (mudar o default de `enabled` para `true` seria MAJOR — registrar que este projeto não pretende fazê-lo)
- Decisão do dono T-6 (cadência semanal) e "opt-in `false` sempre; nunca ligado por update"
- Consome o padrão de `src/Options.php` (ponto único que conhece nomes de option, schema versionado R-09)

## Acceptance Criteria

1. `Options::defaults()` passa a incluir a sub-chave `telemetry` com exatamente estes campos e defaults:
   ```php
   'telemetry' => array(
       'enabled'     => false,
       'instance_id' => '',
       'last_sent'   => 0,
       'last_status' => '',   // 'ok' | 'error' | 'pii_suspected' | ''
       'seq'         => 0,
   ),
   ```
2. `Options::all()` mescla `telemetry` com os defaults do mesmo jeito que já faz com `messages` (sub-array nunca fica parcial; valor gravado inválido/não-array cai para o default).
3. Getters tipados novos em `Options`:
   - `Options::telemetry(): array` — sub-array já mesclado;
   - `Options::telemetry_enabled(): bool` — **resolução única** do estado efetivo (ver AC 4);
   - `Options::telemetry_instance_id(): string`.
4. `Options::telemetry_enabled()` retorna `true` **somente se** `telemetry.enabled === true` **e** `telemetry.instance_id !== ''` **e** nenhuma das constantes de desligamento está definida como verdadeira:
   - `WRF_DISABLE` (já existente — desliga o plugin inteiro, portanto também a telemetria);
   - `WRF_TELEMETRY_DISABLE` (nova — desliga só a telemetria, o resto do plugin segue funcionando).
5. `false` por padrão em **instalação nova** e em **instalação existente que atualiza**. A migração de schema (`maybe_upgrade()` / `SCHEMA_VERSION` incrementado) só **acrescenta a chave `telemetry` com `enabled => false`**; nunca liga, nunca gera `instance_id`, nunca agenda cron. Uma instalação que atualiza fica com o toggle novo desmarcado e nada mais muda.
6. `SCHEMA_VERSION` é incrementado e o bloco correspondente em `maybe_upgrade()` (ou no hook `wp_recaptcha_forms_upgrade_schema`) adiciona `telemetry` a instalações com schema anterior, preservando qualquer outro valor gravado.
7. Nenhuma string traduzida entra em `Options` (disciplina da Story 1.20 — texto da tela fica na Story 1.32; texto de privacidade na Story 1.33).
8. `CHANGELOG.md` `[Unreleased]`: entrada em "Adicionado" citando a opção nova e classificando a mudança como **MINOR** (opção nova retrocompatível). A frase MAJOR do §7 (mudar o default para `true`) é registrada em `Dev Notes` da story e como comentário no código junto ao default.
9. Testes:
   - `telemetry` ausente do array gravado → `Options::telemetry()` devolve os cinco campos com default;
   - `telemetry.enabled = true` mas `instance_id = ''` → `telemetry_enabled()` é `false`;
   - `telemetry.enabled = true` + `instance_id` presente → `true`;
   - `define('WRF_TELEMETRY_DISABLE', true)` → `telemetry_enabled()` é `false` mesmo com opção ligada (processo isolado);
   - `define('WRF_DISABLE', true)` → idem;
   - migração de uma instalação em schema anterior → `telemetry.enabled` fica `false` e as demais opções ficam intactas.

## Dev Agent Record

**Agent Model Used:** claude-opus-5 (@dev / Dex)

**Desvios de implementação, com razão:**

1. **`Options::telemetry_disabled_by_constant()` a mais do que as ACs pedem.** A tela
   (Story 1.32 AC 8) precisa dizer "desativado por constante" em vez de mostrar um
   checkbox que não obedece. Derivar isso de `telemetry_enabled()` seria ambíguo:
   `false` ali também significa "só não optou".
2. **`Options::update_telemetry()` a mais.** Sem ele, cada chamador faria
   `array_merge` do sub-array à mão, e a primeira escrita esquecida deixaria o sub-array
   parcial — exatamente o que a AC 2 existe para impedir.
3. **`OPTION_TELEMETRY_COUNTERS` declarada já nesta story**, não na 1.28. `Options` é o
   ponto único que conhece nome de option (v1 §10); declarar o nome noutro arquivo
   quebraria a regra que torna a migração R-09 possível.
4. **A migração roda só com `$from > 0`.** Schema 0 é instalação nova, que grava
   `defaults()` inteiro logo acima e já vem com `telemetry`. Rodar o bloco ali seria
   escrita redundante.

**Verificado:** `phpunit --filter TelemetryOption` — 9 testes, 24 asserções, incluindo os
dois casos de constante em processo isolado e as duas migrações (aditiva e preservando
opt-in existente).

## Dev Notes
- `WRF_TELEMETRY_DISABLE` segue o mesmo padrão de leitura de `WRF_DISABLE` (constante booleana verificada com `defined() && constant`). Não há UI para ela — é ferramenta de `wp-config.php`.
- Não agendar cron nem gerar `instance_id` aqui. Geração de identificador é a Story 1.27; agendamento é a Story 1.31. Esta story só cria o contrato de dados.
- Registro §7: **este projeto não pretende mudar o default de `telemetry.enabled` para `true`.** Se algum dia mudar, é release MAJOR pelo mesmo raciocínio que torna MAJOR mudar o default de `CLIENT_UNREACHABLE`.
