# Story 1.11 — Registry de integrações + detecção real de WooCommerce

## Status
Draft

## Priority
P1 — Cobertura de formulários (bloqueante para 1.12–1.15)

## Story
**Como** plugin,
**quero** um registry central que carregue integrações nativas incondicionalmente e integrações WooCommerce só sob detecção real (`class_exists` + guard de `implements`),
**para que** o site nunca sofra fatal error com ou sem WooCommerce instalado, e a tela de configurações se gere sozinha.

## Backlog / Arquitetura
- B-12 (base — feature detection), B-13, FR-12/FR-13 (arquitetura v1 §7)

## Acceptance Criteria

1. `Integrations\IntegrationInterface` com `id()`, `label()`, `available(): bool`, `register(): void`.
2. `Integrations\Registry::boot()` registrado em `plugins_loaded` prioridade 20 (depois do Woo). Registra sempre: comentário, login, registro, lost-password nativos, Newsletter (se `NEWSLETTER_VERSION` definida). Registra Woo apenas se `class_exists('WooCommerce')`.
3. **Regra do `implements` (arquitetura v1 §7.1) — crítica:** nenhum arquivo que `implements`/`extends` uma classe/interface do WooCommerce entra no autoload incondicional (Composer). Esses arquivos são carregados via `require_once` explícito, dentro do guard, depois de `interface_exists()`/`class_exists()`. Anotação `@wrf-conditional-load` no topo de cada arquivo assim, e teste de CI que verifica que arquivos anotados não aparecem no autoload gerado.
4. Checkout Blocks: registrado só se `version_compare(WC()->version, '8.3', '>=')` **e** `interface_exists(IntegrationInterface::class)` do Woo Blocks — abaixo disso, a linha aparece na UI como indisponível com o motivo ("requer WooCommerce 8.3+"), não oculta.
5. A tela de configurações (Story 1.5) é **gerada a partir do Registry** — sem Woo, nenhuma integração Woo existe no registry e a seção não é renderizada. Zero condicional de UI escrita à mão.
6. Ativação/desativação do Woo em runtime: toggles Woo salvos **não são apagados** quando o Woo é desativado; reativar restaura a configuração anterior. `uninstall.php` (Story 1.1) apaga tudo, inclusive opções Woo.
7. Teste que ativa o plugin **sem** WooCommerce instalado: zero fatal error, zero notice, `wp_die` nenhum. Teste que ativa **com** WooCommerce: seção Woo aparece completa.

## Dev Notes
- Esta story é a fundação de W-1/W-2/W-3 (Stories 1.12–1.14) e de reviews/lost-password Woo (Story 1.15). Nenhuma delas começa sem o Registry pronto.
- Arquitetura v1 §7.1 é a seção mais importante desta story: o erro fatal clássico de plugins Woo não vem de `class_exists` insuficiente, vem de `implements` resolvido no load da classe antes de qualquer guard rodar.
- `BlocksCheckoutIntegration.php` é criado nesta story só como arquivo vazio/esqueleto anotado `@wrf-conditional-load` — a implementação real é da Story 1.14.
